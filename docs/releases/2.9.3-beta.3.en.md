# PulseDeck 2.9.3-beta.3

## Live update-network transport fix

During the real beta.1 → beta.2 test on Windows, GitHub remained reachable in the
browser while PulseDeck's built-in application and component checks reported that
they could not reach the server.

This prerelease hardens the update transport:

- Chromium `net.fetch` remains the first choice and keeps system proxy/PAC support.
- If Electron fails at the raw network-transport layer before a valid HTTP response
  (including manual-redirect failures), the request is retried with built-in Node HTTPS.
- The fallback is not used for untrusted URLs, HTTP 403/429, timeouts, cancellation,
  size/hash/signature failures, or other policy/integrity errors.
- Native HTTPS redirects still pass the same hop-by-hop allowlist validation.
- yt-dlp and FFmpeg/FFprobe remain independent publisher-managed components.

Install this prerelease manually over beta.1/beta.2, then publish one more beta to
validate the complete in-app update path from the fixed build.

The installer is not Authenticode-signed yet. PulseDeck's internal signed update feed
and SHA-256 verification are separate from Windows SmartScreen.
