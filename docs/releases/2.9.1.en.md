# PulseDeck 2.9.1

26 September 2026

Search preserves typed spaces, including a trailing space after debounce. Source
chips have vector icons and animated enabled states, with no dashed error outline
or visible horizontal scrollbar. Wheel/pan scrolling and handle reordering remain.
Toolbar actions use icons with accessible names and tooltips. Filters open in a
separate animated top-layer popup without shrinking results. Provider errors and
retry actions are available behind the more button next to the result count.
Redundant strip instructions and the search footer were removed.

Preview audio shares the main volume and mute state, with a mute button beside the
timer. The stop button stays on the same row. An empty local library offers one
unified Find options action without a square background.

Settings no longer scroll the entire modal when the global surface switch changes.
The hidden checkbox is anchored inside its own row; only page contents scroll.
The switch label is vertically centered.

Component updates no longer depend on the PulseDeck application repository.
yt-dlp and FFmpeg/FFprobe have their own check action and publisher discovery over
HTTPS with SHA-256. Upstream metadata is not represented as PulseDeck-signed data;
configured signed component catalogs remain supported.

Setup provisions pinned components into <installation>/components before committing
application code. Missing FFprobe makes the FFmpeg pair incomplete and repairable.
Executable tools are never resolved from PATH, external AppData or other installs.
The component storage mapping is backed up and redirected without moving user music,
settings, lyrics or translations. This is not a fully portable user-profile migration.

Pins: yt-dlp 2026.08.19 and FFmpeg/FFprobe 9.0.2. Component binaries and Electron are
not embedded; first installation requires network access. Setup does not report
success when required component provisioning fails.

Actual Windows installation, executable launching and live provider downloads were
not verified in the build environment. Renderer checks use Chromium and component
transaction checks use controlled downloads/probes. The installer is not Authenticode
signed. Provider failures are disclosed on demand, not claimed to have disappeared.
