# PulseDeck 2.9.5 — проверка и применение

## База и границы

Изменения подготовлены относительно предоставленного `PulseDeck-2.9.4-source (2).zip`, а не предположительно совпадающего текущего `main`. Исходная база прошла 747 Node-тестов. Публичный ключ и `app/updates/config.json` не изменены. Приватный ключ не нужен для тестов, исходников и локальной проверочной сборки.

Здесь не выполнялись `git push`, GitHub Actions, публикация релиза или установка EXE в Windows. Chromium-тесты загружают настоящий HTML/CSS/JS приложения, но используют контролируемый IPC. Node-тесты проверяют реальные файловые операции, журнал восстановления, шифрование/поток, FFmpeg-анализ и доверенный main-process с Electron test doubles. Это не замена проверке реального Windows Shell и нескольких физических мониторов.

## Воспроизведение проверок

```bash
node --test tests/*.test.js
node tools/audit-i18n.js
python3 tools/build-release.py
(cd native && go test -race ./...)
(cd installer/engine && go test -race ./...)
python3 tools/run-browser-tests.py
```

Нужны Node, Python, Go, зависимости `tests/requirements.txt`, Chromium и FFmpeg для тестовых fixtures. Системный FFmpeg используется только тестами; производственный анализ ищет компонент через менеджер PulseDeck. Команда `build-release.py` без `--runtime-zip` проверяет кросс-компиляцию веб-установщика, а не собирает окончательный официальный offline-релиз.

Полный итог локального прогона приложен к передаваемому архиву как `PulseDeck-2.9.5-verification.txt`.

## Применение патча на Ubuntu

Сначала проверь рабочую копию; не накладывай патч поверх незакоммиченных изменений:

```bash
cd ~/PulseDeck
git status --short
git log -1 --oneline
```

Когда рабочее дерево чистое:

```bash
git pull --ff-only
git status --short
git log -1 --oneline
# Укажи фактический путь к скачанному патчу:
PATCH="$HOME/Downloads/PulseDeck-2.9.5.patch"
git apply --check "$PATCH"
git apply "$PATCH"
git diff --check
git status --short
git diff --stat
```

Если `git apply --check` не проходит, остановись: `main` отличается от базы архива. Не применяй `--reject`, `reset --hard` или копирование поверх дерева с надеждой автоматически разрешить различия. Сначала сравни конфликтующие файлы с приложенным исходным архивом 2.9.5.

После локальных проверок и просмотра diff:

```bash
git add app installer native tests tools README.md docs
git commit -m "Prepare PulseDeck 2.9.5: library folders, presets and player fixes"
git push
```

Дождись **Tests and Windows build**. При ошибке изучи соответствующий `.log` в `ci-logs-*` и скриншоты/JSON в `ci-evidence-*`; предыдущая нестабильность browser-тестов сама по себе не доказывает, что новая ошибка — flaky.

После зелёного CI запусти **Build a signed-feed release draft** на `main`. Проверь версию и assets в Draft. `2.9.5` — stable, а не beta: для него нужен stable feed. Не помечай его Pre-release и не подменяй официальный EXE после публикации. Если номер 2.9.5 к этому моменту уже опубликован с другим бинарником, сначала синхронно выбери следующий свободный номер.

## Обязательная ручная приёмка Windows

1. **Резервная копия.** Закрой приложение, сохрани `music`, `data`, `%APPDATA%\PulseDeck` и скрытые файлы; используй тестовую копию библиотеки. Новые папки меняют пути аудиофайлов, поэтому простой откат EXE на 2.9.4 не отменяет перенесённые файлы/новые настройки.
2. **Панель задач.** Новая установка и обновление поверх 2.9.4; стандартная и пользовательская иконка; закрепление работающего окна; закрытие и запуск через закреплённый ярлык; отсутствие второй группы окон; чужие ярлыки не меняются. При старом кэше Explorer может потребоваться один раз открепить и закрепить PulseDeck заново. Запуск/закрепление произвольной старой копии EXE не считается проверкой текущей установки.
3. **Геометрия.** Поставь плеер вплотную к нижней границе экрана поверх панели задач, измени размер, закрой и открой приложение несколько раз. Повтори при DPI 100/125/150%, на вторичном мониторе слева/выше основного, после отключения монитора и после смены основного. На неизменном рабочем столе размер/положение должны совпадать; при исчезнувшем мониторе окно должно оставаться доступным.
4. **Папки.** Создай две папки, перенеси пользовательский плейлист и «Все», проверь независимые системные разделы. Верни треки в общую папку. Проверь одинаковые имена файлов, внешне заблокированный файл, отсутствие прав и большой набор треков. Не удаляй `folder-operation.json` вручную после ошибки: он нужен для безопасного восстановления. Защищённый пользовательский плейлист должен сохранить пароль и доступ; автоматическое перемещение защищённых системных разделов должно отказать без раскрытия файлов.
5. **Настройки и фон.** Применяй пресеты с разными секциями при воспроизведении, проверь иконку/горячие клавиши/размер плеера. Открой MP4/WebM/GIF в фоне текста, перезапусти, заблокируй защищённый плейлист, проверь отзыв потока. Декодирование конкретных кодеков зависит от среды Electron.

## Осознанные ограничения

Папки не разделяют права Windows-пользователей; парольная защита остаётся отдельной функцией. Переименование папки не переименовывает её каталог. Перенос музыки — отдельная подтверждаемая команда: добавление трека в плейлист другого физического раздела требует предварительного переноса. Пресеты ссылаются на пользовательские медиа этого компьютера, не включают музыку/секреты и не являются экспортом всей установки. Неудачно проанализированные треки не получают выдуманную громкость: они остаются в конце сортировки с сообщением. Смена топологии мониторов намеренно ограничивает окно доступным экраном, а не гарантирует старые физические пиксели.
