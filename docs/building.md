# Сборка, тесты и состав выпуска

## Требования

Node.js 22+ (локальная проверка: 22.16.0), Go 1.23+ (локально 1.23.2), Python 3.10+
(локально 3.13). Код выполнения не требует `npm install`. Версия Electron, его
точный SHA-256 и официальные адреса находятся в `installer/runtime.json`.
Закрепление унаследовано из переданной 2.7.1; в этой среде архив Electron
повторно не скачивался. Веб-установщик не принимает среду с другим хешем.

```sh
node --test --test-timeout=180000 tests/*.test.js
node tools/audit-i18n.js
python tools/build-release.py
(cd native && go test -race -count=1 ./...)
(cd installer/engine && go test -race -count=1 ./...)
python tools/extract-embedded.py dist/PulseDeck-Setup-2.9.1.exe extracted
python tools/package-source.py
```

Go-тесты движка идут **после генерации payload**, иначе `go:embed` не найдёт
`installer/engine/payload.bin`. `--payload-only` генерирует его без сборки Setup.
Исходники сами по себе не содержат готового native-помощника: он пересобирается
каждый раз. Параметр `--rebuild-native` сохранён как совместимый и избыточный.

Архив payload содержит `app`, `installer/ui`, манифест SHA-256/размеров каждого
файла. Не включает музыку, профиль, токены, закрытые ключи или проверочный runtime.
Опционально туда добавляется только проверенный `runtime/electron.zip`.
Go EXE собирается с `-H=windowsgui`: консоль не нужна. Детерминированные ZIP-даты,
сортировка и `-trimpath -buildvcs=false` устраняют временные пути/даты из сборки.
Побайтовое повторение требует тех же входных файлов и версии Go/toolchain.

## Визуальные тесты

```sh
python -m pip install -r tests/requirements.txt
python -m playwright install --with-deps chromium
python tools/run-browser-tests.py
```

На Linux ожидается `chromium` в PATH; CI связывает скачанный Playwright Chromium
с `/usr/bin/chromium`. Новый тест также понимает `CHROMIUM_EXECUTABLE`.
Регрессии аудио используют установленный `ffmpeg`/`ffprobe` для синтетических
фикстур. Тесты серверов не подключаются к YouTube или личным аккаунтам.
Системный FFmpeg нужен только генератору тестовых фикстур, не production-resolver.
Тесты установки компонентов используют подменённый транспорт и probe; они
проверяют файловые операции и отказоустойчивость, не реальный запуск Windows EXE.

`tests/browser-release-280.py` проверяет настоящий HTML/CSS/JS приложения и
установщика с тестовым IPC и локальным сервером: ссылки, раскрытия, состояния
обновления, сохранение переключателей, ошибки, блокировки, размеры окон и языки.
Это **не** интерактивная проверка Windows/Electron, DPI Win32, ярлыков, UAC,
SmartScreen, эксклюзивных аудиодрайверов или RTSS в игре.

## Запуск приложения из кода

Установленный совместимый Electron запускается с путём `app/`; отдельный npm
пакет приложения не включает Electron автоматически. На Windows разработчик
может использовать проверенную распакованную среду из `installer/runtime.json`.
Не запускайте renderer напрямую с Node integration; обязательны production preload,
contextIsolation и sandbox. HTML-установщик в производстве запускается bootstrap:
самостоятельный запуск без `maintenance.exe` не выполняет установку.

## Исходники для публикации

`tools/package-source.py` создаёт архив обычного дерева проекта, отбрасывая
`.git`, результаты/логи, `dist`, `node_modules`, пользовательские папки,
скомпилированные EXE/DLL, приватные ключи и шрифтовые файлы. Внутри генерируется
`SOURCE_MANIFEST_SHA256.txt`. Подробные скриншоты и логи размещайте как отдельные
CI-артефакты. Статические PNG/ICO/SVG приложения и синтетические тестовые аудио
сохраняются — это необходимые входные данные.

Новый EXE включает runtime/Chromium лицензионные уведомления при распаковке
проверенного runtime. `app/licenses` собирается из `licenses/`, корневых MIT и
CREDITS. Не переносите сгенерированную копию лицензий обратно в исходный набор.

Для восстановления старого SVG дополнительно нужны пакеты из старой инструкции
`design-source`; это не требуется для обычной сборки. Предоставленные готовые
вектор/растр уже входят в исходники, новые социальные SVG сохранены без шрифтов.
