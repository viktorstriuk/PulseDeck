# Инженерные решения 2.8.0 и первичные источники

Дата исследования: 23 сентября 2026. Это обоснование реализации, а не отчёт об
интерактивном тестировании Windows. Фактические результаты проверок находятся в
отдельном отчёте выпуска. Документация upstream может меняться.

## Что принято из требований автора

MusheP сообщил, что предоставленные иконки плейлистов и исходные формы взяты с
SVG Repo с маркировкой Public Domain; знак PulseDeck — его собственная композиция
трёх таких форм. Мы сохранили это как **заявление автора**, а не результат проверки
индивидуальных страниц. Общая страница SVG Repo не доказывает лицензирование каждой
конкретной картинки. Предоставленные PNG автора и `link.svg` используются без
перерисовки. Происхождение и хеши — `docs/assets-provenance.json`.

## Собственный интерфейс установки

Требование полностью собственных кнопок, выбора папки и выступающего логотипа
реализовано локальным Electron HTML/CSS-интерфейсом поверх прозрачного frameless
окна. Выступ находится за краем **нарисованной панели**, но не за границей
настоящего окна ОС. Собственное Go-окно начальной подготовки рисует содержимое
само; оно не использует стандартные страницы мастера или MessageBox.

Официальная документация описывает frameless/transparent окна и ограничения:
https://www.electronjs.org/docs/latest/tutorial/custom-window-styles

Стандартные страницы NSIS не использованы. Поддержка собственной системы установки
означает дополнительную ответственность за транзакции, сохранение данных, откат и
проверку установленного приложения на Windows. Наличие Chromium-скриншотов не
доказывает правильность Win32-прозрачности, DPI или процесса перезапуска.

## Разделение доверия

При реализации использованы рекомендации Electron: локальный интерфейс, sandbox,
contextIsolation, запрет Node.js в renderer, ограничение новых окон/навигации,
проверка отправителя IPC, явные узкие IPC-команды, отсутствие токена GitHub в клиенте.
Не утверждается, что собственный updater прошёл независимый аудит безопасности.

https://www.electronjs.org/docs/latest/tutorial/security
https://www.electronjs.org/docs/latest/api/context-bridge

Выбран собственный небольшой updater на стандартных модулях Node.js, а не
`electron-updater`. Точная байтовая полезная нагрузка feed подписывается Ed25519;
публичный ключ задаётся в приложении, не берётся из feed. Хеш полученного EXE
сравнивается с подписанным описанием. Это не Authenticode и не обещание отсутствия
предупреждений Windows. Проверка ограничений URL/TLS, размера, тайм-аутов, версии,
канала и защиты от повторного запуска ошибочного обновления — код PulseDeck.

https://nodejs.org/api/crypto.html#cryptoverifyalgorithm-data-key-signature-callback
https://nodejs.org/api/https.html

## Публикация

GitHub Releases используются как будущий хостинг бинарников и подписанных feed;
адрес репозитория и публичный ключ в поставке оставлены пустыми. Предусмотрены
защищённый release environment, ручная публикация draft, отдельный секрет ключа,
фиксированные SHA Actions, отсутствие выпуска из pull request. Workflow подготовлен,
но на реальном репозитории ещё не запускался.

https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases
https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions
https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases

При подготовке проверены официальные страницы релизов Actions и их commits:
checkout v7.0.1, setup-node v7.0.0, setup-go v7.0.0, upload-artifact v7.0.1.
Точные SHA зафиксированы в `.github/workflows/`. Это не плавающие теги.
