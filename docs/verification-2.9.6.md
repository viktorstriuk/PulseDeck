# Проверка PulseDeck 2.9.6

## База и границы достоверности

Патч подготовлен из переданного архива `PulseDeck-2.9.5-source.zip` с SHA-256
`c1d9d61c278af08229beffc3eb0780f910e77f329e75e08762fc082cc1bbfdd8`.
На этапе подготовки веб-представление `main/app/package.json` показывало 2.9.5.
Получить Git-клон и доказать точный HEAD официального `main` не удалось: среда
не разрешала `github.com` для Git. Локальный технический baseline-коммит не является
коммитом официального репозитория. Перед применением обязательны `git pull`,
проверка чистого дерева, сравнение Git blob ID базовых файлов и `git apply --check`.
При несовпадении базы патч не следует накладывать принудительно.

Это изменение исходников, а не опубликованный или подписанный официальный EXE.
Ключи и конфигурация доверия обновлений не меняются. Исходные signed feeds 2.9.5
не редактируются и не используются как новые feeds 2.9.6.

## Автоматические проверки

```powershell
node --test tests/*.test.js
node tools/audit-i18n.js
python tools/build-release.py
Push-Location native
try { go test -race ./... } finally { Pop-Location }
Push-Location installer/engine
try { go test -race ./... } finally { Pop-Location }
python tools/run-browser-tests.py
```

На Windows для тестов реального FFmpeg укажите абсолютные пути тестовых инструментов:
`PULSEDECK_TEST_FFMPEG` и `PULSEDECK_TEST_FFPROBE`. Это переменные тестового процесса,
а не разрешение приложению искать инструменты по PATH. Browser-runner в CI работает
на Linux; для локального Chromium задаётся `CHROMIUM_PATH`. Race detector Go требует
C toolchain. Не устанавливайте дополнительные инструменты только ради применения
патча: полный набор также выполняет существующий workflow **Tests and Windows build**.

`tests/media-296.test.js` проверяет нормализацию и ограничения, восстановление
сдвига/дрейфа на синтетическом PCM, отказ от неоднозначного совпадения, реальный
FFmpeg LUFS/VP9/Opus/обрезку, ограничение задач и отмену, writable fsync, независимость
клипа от обложки/текста, перемещение, Vault-шифрование, range-запросы и отзыв доступа,
проверку IPC-отправителя и протокол подтверждения запуска.

`tests/browser-media-296.py` загружает настоящий renderer в Chromium. DOM, Web Audio,
декодирование и транспорт реальны. IPC, сетевые поисковые ответы и аудиоустройства
заменены детерминированными тестовыми мостами. Локальный медиасервер реализует
HTTP Range/206: обычный SimpleHTTPRequestHandler без Range делает файл неперематываемым
и не является корректным заменителем file:// или защищённого медиасервера.

`installer/engine/transaction_296_test.go` проверяет ресурс VERSIONINFO,
очистку окружения, порядок branding/commit и отсутствие ложного события done при
ошибке запуска. Кросс-компиляция проверяет Windows-код, но не исполняет Windows API.

Браузерные снимки и логи создаются в `test-results/2.9.6`; это игнорируемые артефакты,
не исходники. Отчёт конкретного прогона поставляется рядом с патчем.

## Реальная Windows 11: обязательная приёмка до Publish

1. В резервной копии тестовой библиотеки переместить треки между папками, включая
   имена с кириллицей, совпадающие имена, воспроизводимый файл, обложку, текст и клип.
   Проверить отсутствие EPERM, сохранение байтов и ссылок. Смоделировать отказ записи
   и убедиться, что нет потери исходника или частично применённой организации.
2. Переключать папки/плейлисты мышью и клавиатурой: без мигания кнопок, с рабочим
   контекстным меню, сортировкой, drag и undo/redo. Проверить оба расположения панелей.
3. Установить официальный кандидат поверх 2.9.5 в прежнюю папку. Проверить имя
   PulseDeck в свойствах EXE и при новом закреплении; отдельно проверить старое
   закрепление. Если Explorer сохранил старый текст — один раз открепить и закрепить
   обновлённое приложение, не очищая Taskband реестра и не трогая чужие ярлыки.
4. Проверить автоматический restart из updater и кнопку «Запустить PulseDeck»,
   включая уже запущенный экземпляр, путь с пробелами/кириллицей, медленную загрузку,
   ошибку запуска и повтор. Установщик должен оставаться отзывчивым, показывать
   отчёт при ошибке и не объявлять скрытый/упавший процесс успешным запуском.
5. Выбрать реальные динамики, USB-гарнитуру и Bluetooth-выход. Проверить системный
   default при смене устройства в ОС, предложение нового выхода, отключение и
   возврат выбранного устройства. Прослушать библиотеку, онлайн-результат,
   audio trim, video trim, видеоклип и sound test; проверить master/mute везде.
6. Сравнить тихую и громкую песни с выключенной/включённой нормализацией. Проверить
   все четыре эталона, допуск и предел усиления. Двигать ползунок во время анализа.
   Проверить старые пресеты, сохранение новых звуковых настроек и тихий тест без треков.
7. С настоящим YouTube подготовить клип, независимо обрезать и сохранить. Проверить
   точное ручное связывание и автосинхронизацию в начале, середине, конце, включая
   другое вступление, иной мастер, повторяющуюся музыку и другую концертную версию.
   Неуверенное совпадение не должно применяться. Недоступность сервиса не является
   основанием обходить DRM, географические или авторизационные ограничения.
8. Переключать звук/видео на паузе и при воспроизведении, менять позицию, трек и
   громкость во время подготовки; проверить Alt+Shift+V и пользовательское
   переназначение, Escape, отсутствие двойного звука, область без совпадения и
   независимые длительности. Проверить фоновое видео текста и обычную обложку.
9. В audio trim нажать «Добавить видеоклип»: разные границы, сохранение обоих файлов,
   ошибка сохранения видео и повтор без дубликата аудио, отмена/закрытие во время
   загрузки. Защитить и разблокировать плейлист с клипом, отозвать поток при lock,
   затем явно снять защиту: клип и фон должны сохраниться, открытых копий в staging
   после отмены/завершения быть не должно.
10. После зелёного CI запустить **Build a signed-feed release draft** на `main`.
    До публикации проверить номер 2.9.6, SHA256SUMS, подпись feed существующим
    публичным ключом и вручную установить кандидат из Draft на тестовой Windows.
    После успешной предрелизной приёмки нажать Publish release. Затем отдельно
    проверить обнаружение, скачивание и установку updater 2.9.5 → 2.9.6 из
    опубликованного релиза. Обычный updater не обнаруживает неопубликованный Draft;
    проверка его обнаружения не является выполнимым шагом до Publish.

## Осознанные ограничения

Поиск клипов в этой версии — YouTube; существующие музыкальные каталоги используются
для поиска фоновых изображений. Пакетный поиск предлагает кандидатов, не угадывает
правильный клип молча. Максимум источника 30 минут / 2 ГиБ, три подготовленных
источника, две параллельные фоновые задачи и ограниченная очередь. Видео сохраняется
в VP9/Opus WebM. Автосинхронизация — оценка общего сдвига и скорости, не редактор
разных монтажей. Отображаемый процент — качество совпадения сигнала, не статистическая
вероятность абсолютной точности. Анализ полной локальной песни может занять время;
сетевая проба громкости ограничена первыми 20 секундами. Нормализация не заменяет
безопасную системную громкость и не является медицинской гарантией защиты слуха.

Реальные Windows taskbar/устройства/установка и живой YouTube не проверяются
подменёнными IPC-сценариями; не следует выдавать браузерные тесты за такую приёмку.
