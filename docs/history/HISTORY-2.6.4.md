# PulseDeck 2.6.4

Обновление предоставленного проекта **2.6.3**: групповые действия с плейлистами,
перенос песен мышью и защищённые плейлисты с шифрованием файлов и метаданных.

**Сначала сделай резервную копию.** Полностью закрой PulseDeck, включая трей,
скопируй папку приложения с `music` / `data` и `%APPDATA%\PulseDeck`.
Это первая экспериментальная версия зашифрованного хранилища: независимого аудита
безопасности и запуска установщика в Windows в рамках этой работы не было.
Не используй её как единственное место хранения незаменимых файлов.

## Исправления и управление

**Избранное.** Если все выделенные песни уже избранные, меню предлагает
«Убрать их из избранного». При смешанном выделении команда добавления добавляет
недостающие песни, а не переключает все состояния вслепую.

**Точный состав выделения.** Групповые команды используют снимок выбранных ID,
не текущий проигрываемый трек. Причина ложного «Разделить артистов» в 2.6.3:
проверка смотрела на всю группу псевдонимов библиотеки. Теперь для меню треков
нужны несколько исходных артистов одной объединённой группы именно в выделении.
В меню плейлиста разделение по-прежнему учитывает всю его группу. Правила артистов
действуют на все текущие и будущие песни соответствующих артистов; это объясняет
подтверждение. Музыкальные теги не переписываются.

**Перестановка плейлистов.** У горизонтальной перетаскиваемой копии убраны фон,
рамка и тень; у боковой сохранены. Расчёт движения, фиксация оси, границ и
автопрокрутка из 2.6.3 не изменены. Находясь в режиме редактирования, можно тащить
за ручку сразу. Быстрое движение по кнопке тоже переставляет; удержание около
0,34 секунды начинает выделение.

**Контур списка.** Непрерывная группа выбранных строк имеет общую внешнюю обводку,
без горизонтальных рамок между строками. Разорванное выделение получает отдельную
обводку для каждой непрерывной группы. Карточки остаются отдельными.

**Убрать из текущего плейлиста.** Команда есть у одной песни и в групповом меню;
файлы не удаляются. Для артистических, недавних и загруженных песен сохраняется
исключение из соответствующего представления. Для «Все» отдельного удаления
принадлежности нет: это вся открытая библиотека. Из защищённого плейлиста песня
убирается в его зашифрованный архив и может быть возвращена через меню плейлиста.

## Выделение плейлистов и перенос песен

В верхней и боковой панелях работают Ctrl+клик, Shift+клик, удержание с проведением
по кнопкам и выделение от свободного места. Ctrl+A относится к сфокусированной
панели; Esc снимает выделение. После мышиного жеста открывается групповое меню,
также есть кнопка «Действия». Выделение не переключает активный плейлист.

Команды: «Удалить их», «Скрыть их», «Объединить их», а для нескольких артистических
плейлистов — «Считать разных артистов выбранных плейлистов за…». При объединении
выбирается получатель, остальные списки удаляются, музыкальные файлы сохраняются.
Системные разделы можно скрыть или оставить получателем, но нельзя удалить.
Для нескольких защищённых списков добавляется «Объединить доступ».

Быстрое перетаскивание песни на плейлист добавляет её в него. Если перетаскиваемая
песня выделена, переносится вся выбранная группа, иначе только эта песня.
Получатель подсвечивается. На время жеста в конце панели появляется «+»,
без включения режима редактирования плейлистов. Бросок на «+» открывает редактор
создания с названием песни или количеством выбранных песен в заголовке.
Отмена не создаёт плейлист; добавление не меняет исходный порядок треков.
Обычная перестановка внутри списка/карточек, автопрокрутка и Ctrl+Z / Ctrl+Shift+Z /
Ctrl+Y сохранены. История отмены не распространяется на шифрование или удаление файлов.

## Защищённые плейлисты

Переключатель есть при создании и редактировании. Пароль — **3–48 символов Unicode**,
с повтором при создании. Регистр и пробелы значимы. Технический минимум не означает
стойкость: выбирай длинную уникальную парольную фразу. Пароль не записывается на
диск, сброса пароля и служебного ключа восстановления нет.

В `music` создаётся папка с названием плейлиста и коротким случайным суффиксом.
Аудио получает непрозрачные имена `.pda`; названия, артисты, источники, обложки,
исходные пути и ключи файлов записываются в зашифрованный список `playlist.pdv`.
Сначала проверяется зашифрованная копия, затем убираются открытые файлы и ссылки
из обычных разделов, избранного, пользовательских списков и текущего кэша.
При ошибке остаётся предупреждение; программа не считает незавершённый перенос
успешной полной защитой. Не закрывай приложение во время операции.

Папки артистов из 2.6.1 **не возвращались**. Эти папки создаются только по явной
команде защиты. Включение защиты шифрует текущий состав выбранного раздела;
последующее добавление в него выполняется явно, с паролем. Защита артистического
или системного раздела не является правилом фонового шифрования новых импортов.

При входе показывается поле пароля вместо списка. При уходе из плейлиста доступ
закрывается, приватное воспроизведение останавливается; при возвращении пароль
нужен снова. Можно нажать «Заблокировать». Связанные общей группой плейлисты
сохраняют доступ между собой до выхода в другую категорию/блокировки/перезапуска.

Воспроизведение и перемотка используют локальный поток с проверкой целостности
небольших блоков, а не расшифровку всей коллекции в файлы. При закрытии доступа
ссылки потока отзываются. Название самого плейлиста, существование его папки,
размеры файлов и некоторые структурные сведения не скрыты.

### Добавление из защищённого плейлиста

В другой защищённый список: вводятся пароли источника и получателя, добавляется
ссылка на тот же зашифрованный объект без второй копии аудио. Поэтому резервировать
нужно **всю `music`**, а не только одну папку плейлиста.

В обычный список, включая открытое избранное: запрашиваются пароль источника и
согласие на снятие защиты. Песня расшифровывается в корень `music`; зашифрованное
аудио удаляется после успешного экспорта. Защищённые списки с этой песней используют
открытый файл, а интерфейс отмечает наличие открытых копий. Метаданные закрытого
списка остаются зашифрованными, но **сам открытый файл уже доступен без пароля**.
Удаление этой общей открытой песни удаляет её доступность и в защищённых списках.

Правила артистов для приватного выделения требуют пароля и отдельного согласия:
имена артистов и общие правила станут открытой настройкой приложения. Аудио,
названия и обложки при этом остаются внутри защиты.

### Общий доступ, удаление, восстановление

«Объединить доступ» проверяет текущий пароль каждого списка и предлагает общий
пароль с повтором. Списки не сливаются. Личные первоначальные пароли по-прежнему
открывают только свои списки; общий открывает выбранную группу. Разблокировка
раскрывает ключи, метаданные других списков читаются по мере открытия, аудио —
по мере воспроизведения. Это не процедура криптографического отзыва уже известных
паролей у других людей.

Удаление защищённого **плейлиста** оставляет папку как зашифрованный архив.
Вернуть её можно из настроек «Библиотека» с личным паролем. Удаление **песен**
отправляет файлы в корзину и затрагивает все списки, использующие эти же объекты.
Зашифрованные ключи и метаданные удалённых песен сохраняются для восстановления.

В `app/tools/recover-vault.js` есть отдельная утилита извлечения с известным
**личным** паролем, работающая даже без общего индекса. Нужен Node.js 20+:

```powershell
node app/tools/recover-vault.js "D:\PulseDeck\music" "D:\PulseDeck\music\Личное [идентификатор]" "D:\Recovered-PulseDeck"
```

После установки путь к скрипту: `resources/app/tools/recover-vault.js`.
Пароль вводится скрыто в терминале, не параметром командной строки. Выходная папка
должна быть новой и вне `music`; в ней появятся **открытые** песни и отчёт.
Исходники не изменяются. Аудио, удалённое в корзину, сначала нужно восстановить
на диск. Утилита не восстанавливает забытый пароль или физически отсутствующие данные.

Полное описание формата и ограничений: [SECURITY.md](app/vault/SECURITY.md).

## Установка, проверка и сборка

`PulseDeck-Setup-2.6.4.exe` — Windows x64 bootstrap-установщик. Он содержит приложение,
использует совместимые установленные компоненты повторно и загружает недостающие.
Это **не автономный установщик**. Выбирай прежнюю папку установки, предварительно
закрыв предыдущий процесс. Компоненты/контрольные суммы загрузок унаследованы из
2.6.3, их сетевое получение в этом цикле не проверялось. Сборка не подписана.

```bash
node --test tests/*.test.js
python tests/browser-regression.py
python tests/browser-features-263.py
python tests/browser-features-264.py
python tests/browser-vault-264.py
```

Нужны Node.js, Python Playwright и Chromium. Обычные UI-тесты используют настоящий
интерфейс и тестовый IPC-мост. `browser-vault-264.py` использует дополнительно
настоящие временные файлы, криптографические workers, локальный поток и декодер
браузера; нативные оконные API Electron по-прежнему имитируются. Тестовый RPC-сервер
находится только в `tests/` и **не встроен** в установленное приложение.
Результаты и границы проверки: `test-results/TEST-REPORT.md`.

Windows, реальные межоконные сквозные клики/resize, системные горячие клавиши,
корзина Windows, игры, несколько мониторов и онлайн-скачивание в этой среде
не запускались. Проверки кода и Playwright не заменяют такие проверки и аудит.

Сборка установщика из корня, без сторонних Go-модулей:

```bash
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" \
  -o PulseDeck-Setup-2.6.4.exe setup.go
python tools/extract-embedded.py PulseDeck-Setup-2.6.4.exe extracted
```

Go встраивает `app/`; не размещай там личные файлы, пароли или node_modules.
Исходники установленного Electron-приложения находятся в `resources/app`.
`native-reference/` — справочный код первоначального восстановления: соответствие
встроенному `PulseDeck.GameOverlayHost.exe` не установлено, помощник не пересобирался.
Пользовательские SVG сохранены; сведения о происхождении — в
`app/THIRD_PARTY_NOTICES.md`. Файлы шрифтов не включены.
