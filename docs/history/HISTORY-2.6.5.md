# PulseDeck 2.6.5

Исправление двух дефектов игрового оверлея: необработанного `write EPIPE` в Electron
и повторной регистрации Win32 callback в нативном помощнике. База — предоставленные
исходники 2.6.4. Музыкальная библиотека, плейлисты, шифрование и файлы пользователя
в этом обновлении не мигрируют и не перекладываются.

## Установка и обновление

Полностью закрой PulseDeck, включая трей. Сохрани резервные копии папки приложения
с `music` и `data`, а также `%APPDATA%\PulseDeck`.

`PulseDeck-Setup-2.6.5.exe` устанавливается в прежнюю папку. Как в 2.6.4, совместимые
внешние компоненты используются повторно; отсутствующие загружаются по прежним
фиксированным версиям и SHA-256. Это не полностью автономный установщик.

Для **установленной 2.6.4** предусмотрен архив обновления без установщика. Скопируй
из него `resources` в папку, где находится прежний `PulseDeck.exe`, с объединением
папок и заменой файлов. Не удаляй остальные файлы и не копируй `resources` внутрь
другой папки `resources`. Полностью замени новый нативный EXE вместе с JS-кодом:
старый помощник содержит утечку callback-регистраций.

И установщик, и новый `PulseDeck.GameOverlayHost.exe` **не подписаны доверенным
сертификатом**. Архив обновления тоже содержит новый EXE; он не снимает блокировки
Smart App Control/SmartScreen и не отключает защиту Windows. При блокировке
помощника игровая часть сообщает об ошибке; основной проигрыватель не должен
завершаться из-за ошибки его канала.

Защищённые плейлисты 2.6.4 остаются экспериментальными и независимого аудита не
получили. Проверяй их на копиях, а не на единственных экземплярах музыки.

## Что изменено

### Основной процесс

`app/game-overlay/transport.js` владеет процессом, потоками и таймерами. Обработчики
ошибок ставятся на stdin/stdout/stderr и ChildProcess до первой записи. У каждой
записи есть callback; защищены и обычная передача, и команда stop/end.

Очередь содержит только последнее ещё не отправленное сообщение каждого типа и
одну незавершённую запись. `drain` учитывается; старые аудиокадры не накапливаются.
Проверки `killed` больше не подменяют проверку состояния канала. Глобального
подавления `uncaughtException`/`unhandledRejection` нет.

После неожиданной потери связи помощник останавливается. Новый запускается только
после `close` предыдущего. Задержки повторов: 0,5 / 1,5 / 4 / 10 с. После четырёх
неудачных повторов цикл приостанавливается до ручного перезапуска или off→on.
Стабильные 60 секунд сбрасывают счётчик. Отдельные таймауты ограничивают ожидание
hello, остановившейся записи и heartbeat.

После нового hello отправляются **текущие** HWND, конфигурация, песня и цвета,
включая палитру обложки. События старого процесса не могут перезаписать новый статус.
Режимы «Окно Windows» и «Выкл» не запускают помощник. Закрытие приложения отменяет
повторы. Асинхронная ошибка отдельного запуска RTSS тоже обрабатывается.

### Нативный помощник

Точного исходника старого поставляемого EXE в восстановленном архиве нет. Поэтому
подготовлен новый полностью собираемый модуль `native/`. Справочный Go-файл без
RTSS не подставлен вместо рабочего помощника. Сохранены протокол JSON Lines,
shared-memory OSD RTSS, обычный оконный fallback, разрешённые игры, фильтр полного
экрана, позиция, палитра, название/исполнитель/плейлист, прогресс, визуализатор,
информация об API и соотношении сторон. Форматы сверены с прежним бинарником.
Точное попиксельное совпадение RTSS и нативная совместимость с играми без Windows
не подтверждены — это восстановленная реализация, не точный исходник старого EXE.

Win32 callback регистрируется ровно один раз через `sync.Once`. В EnumWindows
передаётся целочисленный токен, а текущий контекст хранится в Go-map и удаляется
при любом завершении опроса. Нет захватывающей новый снимок конфигурации регистрации
внутри каждого прохода.

EOF и stop завершают главный цикл через context cancellation, а не os.Exit из
горутины. Освобождаются собственный OSD-слот, отображение памяти, HANDLE и mutex.
Другие владельцы OSD не очищаются. Проверяются границы shared memory и поле dwBusy.
Занятый RTSS не блокирует статус/heartbeat. Оконный fallback не вызывает ShowWindow
для скрытого плеера и не захватывает фокус.

## Диагностика

`data/logs/game-overlay.jsonl` рядом с приложением, плюс один ротированный файл
`.1`. Лимит — примерно 128 КиБ на файл. Записываются запуск, версия помощника,
коды ошибок, завершение и повторы. Названия песен, аудиокадры, пароли и команды
полностью в журнал не попадают. Это журнал диагностики, не сетевой сбор данных.

Если проблема повторится в Windows, полезны этот журнал, выбранный режим игрового
оверлея и полное сообщение ошибки. Никаких изменений параметров защиты для
сбора журнала не требуется.

## Проверки и ограничения

Результаты текущей сборки — `test-results/TEST-REPORT.md`. Тесты используют реальные
Node pipe/subprocess, модель основного процесса Electron, Chromium/Playwright,
Go race detector и RTSS-структуры в памяти. Реальное выполнение Win32/RTSS,
установщика и Bodycam в этой среде недоступно; Windows-тесты только скомпилированы.
Наличие исходника и прохождение тестов не являются цифровой подписью или аудитом.

## Пересборка

Нужны Go и Python 3. Код helper не имеет внешних Go-зависимостей.

```sh
python tools/build-release.py
```

Скрипт собирает **помощник первым**, затем встраивающий его установщик и повторно
собирает помощник для проверки совпадения. Результат — `dist/` (не входит в исходный
архив). Извлечь embed.FS для независимого сравнения:

```sh
python tools/extract-embedded.py dist/PulseDeck-Setup-2.6.5.exe extracted
```

Проверки:

```sh
node --test tests/*.test.js
cd native
go test -race -count=1 ./...
go test -run='^$' -fuzz=FuzzRTSSLayout -fuzztime=5s -parallel=2
```

Playwright: `python tests/browser-regression.py`, затем аналогично остальные
`browser-*.py` кроме `browser-bridge.js`; нужен доступный Chromium. Тестовые мосты
находятся только в `tests/`, не в поставляемом приложении.

На Windows с Go отдельно: `cd native` и
`go test -run Windows -count=1` — это настоящий EnumWindows (10 000 опросов) и
проверка размеров Win32-структур. В Linux эти два теста не исполняются.

История функций 2.6.4: `HISTORY-2.6.4.md`. Старые отчёты в `test-results/history-*`
не являются результатами проверки 2.6.5.
